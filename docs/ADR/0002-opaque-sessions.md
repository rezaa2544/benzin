# ADR-0002 — توکن مات سمت سرور به‌جای JWT

**وضعیت:** پذیرفته‌شده

## زمینه

ورود با OTP است؛ کاربر باید بتواند «خروج از همه‌ی دستگاه‌ها» را بزند و ادمین باید بتواند
نشست یک حساب مشکل‌دار را فوراً باطل کند.

## تصمیم

توکن دسترسی یک رشته‌ی تصادفی مات است که در جدول نشست‌ها (فعلاً `sessions`، بعداً
`refresh_tokens`) نگه‌داری می‌شود؛ اعتبارسنجی با یک lookup و بررسی `expires_at`/`revoked_at`.
JWT فقط اگر روزی چند نمونه‌ی API بدون پایگاه‌داده‌ی مشترک لازم شد کنار گذاشته می‌شود.

## پیامدها

- ابطال فوری ممکن است؛ هیچ توکنی بعد از خروج معتبر نمی‌ماند.
- هزینه: یک کوئری در هر درخواست (با ایندکس یکتا، ارزان). در فاز بار می‌توان کش کرد.
- فرض A4 در `ASSUMPTIONS.md` همین تصمیم را ثبت می‌کند.
