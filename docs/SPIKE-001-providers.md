# SPIKE-001 — ارائه‌دهنده‌ی پیامک، درگاه پرداخت، Push و نقشه

تسک مرتبط: **E0-04**. وضعیت: Proposed (منتظر تأیید مالک).

## چرا

سه ریسک بیرونی می‌تواند کل محصول را متوقف کند: تحریم/قطعی درگاه پیامک، نبود درگاه پرداخت
قابل اتکا، و دسترسی نداشتن به FCM و نقشه‌های جهانی از داخل ایران. کد از روز اول پشت
Interface نوشته می‌شود تا انتخاب ارائه‌دهنده یک تغییر پیکربندی باشد، نه بازنویسی.

## نتیجه‌ی بررسی (خلاصه)

| نیاز            | گزینه‌ها                            | توصیه                                                                   |
| --------------- | ----------------------------------- | ----------------------------------------------------------------------- |
| پیامک OTP       | کاوه‌نگار، SMS.ir، قاصدک، ملی‌پیامک | کاوه‌نگار (الگوی آماده + وب‌سرویس ساده) با fallback به SMS.ir           |
| درگاه پرداخت    | زرین‌پال، زیبال، آیدی‌پی            | زرین‌پال (تست پذیرنده‌ی خوب، تسویه‌ی سریع)                              |
| Push            | FCM، وب‌پوش PWA، پیامک جایگزین      | وب‌پوش + FCM؛ برای اندروید در صورت محدودیت، پیامک به‌عنوان کانال تضمینی |
| نقشه/مسیریابی   | نشان، بلد، OSM+OSRM خودمیزبان       | نشان برای نقشه (ایران)، OSRM خودمیزبان برای مسیر و ETA                  |
| ذخیره‌سازی فایل | S3-سازگار داخلی، مین‌ایو خودمیزبان  | مین‌ایو روی همان VPS                                                    |

**مکانیزم کارت‌به‌کارت (D7)** ریسک اصلی است: بدون API بانکی، تأیید واریز باید یا با
«مبلغ یکتا» و ingestion پیامک بانکی روی سرور انجام شود، یا با تأیید دستی ادمین. پیش‌فرض:
مبلغ یکتا + تأیید دستی؛ ارتقا به ingestion وقتی مالک منبع پیامک بانکی را تأیید کند.

## گام بعدی

مالک یکی از گزینه‌ها را تأیید می‌کند → تسک E1-03 (ارسال OTP) و E5 (پرداخت) با همان ارائه‌دهنده
پیاده‌سازی می‌شود. کد فعلی فقط `SmsSender` را می‌شناسد و در توسعه پیام را در لاگ می‌نویسد.
