# SPIKE-001 — ارائه‌دهنده‌ی پیامک، درگاه پرداخت، Push و نقشه

تسک مرتبط: **E0-04** · تصمیم‌های باز: **D3** (پیامک/درگاه/Push) و **D4** (نقشه و مسیریابی)
وضعیت: **Proposed** — پیشنهاد آماده است، اجرا پس از تأیید مالک.

## ۱. تصمیم پیشنهادی در یک نگاه

| تصمیم             | پیشنهاد                                                                                  | جایگزین آماده     | چرا این یکی                                                                                                                                                                                              |
| ----------------- | ---------------------------------------------------------------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D3 · پیامک OTP    | **SMS.ir** به‌عنوان مسیر اصلی، **کاوه‌نگار** به‌عنوان مسیر پشتیبان                       | ملی‌پیامک، قاصدک  | SMS.ir محیط Sandbox مستند دارد (برای CI و تست بدون هزینه)، الگوی آماده (`/v1/send/verify`) و پنل ساده‌ی الگو دارد؛ کاوه‌نگار با `verify/lookup` بالغ‌ترین API ایرانی است و تجربه‌ی طولانی در خطوط خدماتی |
| D3 · درگاه پرداخت | **زرین‌پال**                                                                             | زیبال، آیدی‌پی    | سندباکس بدون مرچنت واقعی، مستندات REST روشن، سابقه‌ی طولانی؛ **فقط** برای پلن‌های پولی و «شارژ اعتبار»، نه برای هر معامله                                                                                |
| D3 · Push         | **وب‌پوش (VAPID)** اکنون، **FCM** برای اپ اندروید در M1، **پیامک به‌عنوان کانال تضمینی** | —                 | وب‌پوش زیرساخت خارجی و مجوز نیست؛ FCM از داخل ایران قابل اتکا نیست، پس اعلان بحرانی هرگز فقط روی Push نمی‌ماند                                                                                           |
| D4 · نقشه         | **نشان** برای نقشه و Geocoding                                                           | بلد، OSM خودمیزان | سرویس ایرانی با پوشش خوب شهرهای کوچک، Distance Matrix با ترافیک، تعرفه‌ی شفاف و اعتبار ماهانه‌ی هدیه                                                                                                     |
| D4 · مسیریابی/ETA | **نشان Direction** در تولید، **Valhalla/OSRM خودمیزان** به‌عنوان نقشه‌ی پشتیبان          | —                 | ETA ترافیکی برای «زمان رسیدن» مفید است، ولی مسیر باید در قطعی/تحریم هم کار کند                                                                                                                           |

قاعده‌ی ثابت هر دو تصمیم: **هیچ‌کدام از این سرویس‌ها در لایه‌ی دامنه دیده نمی‌شوند.** کد امروز فقط
`SmsSender`، `PaymentProvider` و `RouteProvider` را می‌شناسد؛ انتخاب ارائه‌دهنده یک آداپتور و چند
متغیر محیطی است، نه بازنویسی.

## ۲. آنچه امروز در کد هست (و بنابراین هزینه‌ی تغییر)

| نقطه‌ی اتصال      | فایل                                                       | وضعیت امروز                                                                                           |
| ----------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `SmsSender`       | `apps/api/src/ports.ts`، پیاده‌سازی `ConsoleSmsSender`     | پیام در لاگ نوشته می‌شود؛ پنل ادمین هم دکمه‌ی «پیامک آزمایشی» دارد (E8)                               |
| `PaymentProvider` | `apps/api/src/modules/payment-providers.ts`                | `CardToCardProvider` (مبلغ یکتا + تأیید دستی) و `SandboxGatewayProvider` با `PAYMENT_GATEWAY=sandbox` |
| `RouteProvider`   | `apps/api/src/ports.ts`، فراخوانی در `location-service.ts` | بدون کلید، فاصله‌ی مستقیم (haversine) و ETA تقریبی                                                    |
| Push              | —                                                          | هنوز پیاده نشده؛ اعلان‌ها فعلاً در‌ونو (in-app) هستند                                                  |

یعنی تصمیم D3 امروز صفر خط کد جدید لازم ندارد؛ فقط یک کلاس آداپتور + سه متغیر محیطی
(`SMS_PROVIDER`، `SMS_API_KEY`، `SMS_SENDER_LINE`). تصمیم D4 هم فقط `ROUTING_PROVIDER` و
`NESHAN_API_KEY` را به `RouteProvider` وصل می‌کند.

## ۳. پیامک

معیارها: امکان استفاده از داخل ایران، کیفیت الگوی OTP، محیط تست، تعرفه، کیفیت مستندات، ریسک قطعی.

| معیار                    | SMS.ir                                                                  | کاوه‌نگار                                            | ملی‌پیامک   | قاصدک       |
| ------------------------ | ----------------------------------------------------------------------- | ---------------------------------------------------- | ----------- | ----------- |
| API الگوی OTP            | `POST /v1/send/verify` با `x-api-key` + `templateId` + پارامترها (JSON) | `verify/lookup` با کلید و الگو (JSON ساده)           | REST + الگو | REST + الگو |
| محیط Sandbox مستند       | **دارد** (همان URL با تنظیم Sandbox)                                    | ندارد (اعتبار آزمایشی)                               | ندارد       | ندارد       |
| مستندات فارسی/نمونه‌ی کد | بسیار خوب، نمونه برای Node/PHP/Python/C#                                | خوب، `rest.html` کامل با جدول خطاها                  | متوسط       | متوسط       |
| تعرفه                    | بسته به پنل؛ **استعلام لازم**                                           | بسته‌ی سالانه‌ی پیشرفته ۶۰۰٬۰۰۰ تومان + اعتبار پیامک | استعلام     | استعلام     |
| خط خدماتی/الگو           | دارد                                                                    | دارد (سابقه‌ی طولانی)                                | دارد        | دارد        |
| ریسک قطعی                | متوسط                                                                   | متوسط                                                | متوسط       | متوسط       |
| مناسب برای               | مسیر اصلی (Sandbox برای CI)                                             | مسیر پشتیبان با API بالغ                             | جایگزین     | جایگزین     |

**تعرفه – واقعیت پایه:** تعرفه‌ی رسمی اپراتور در ۱۴۰۴ بین **۸۸ تا ۳۰۴ ریال** برای هر پیامک است
(بسته به دائمی/اعتباری و فارسی/لاتین). قیمتی که پنل‌ها برای خط خدماتی و پیامک الگویی می‌گیرند
روی این عدد حاشیه دارد و **باید در زمان قرارداد استعلام شود**؛ در مدل هزینه‌ی بخش ۵ فرض
۱۵۰ تومان برای هر OTP گرفته‌ایم و حساسیت را با ۱۰۰ و ۲۰۰ تومان هم نشان داده‌ایم.

**نکته‌ی مهندسی:** Failover واقعی یعنی اگر ارسال اصلی خطا داد یا تایم‌اوت شد، تلاش دوم روی
ارائه‌دهنده‌ی پشتیبان انجام شود و **هر دو** در لاگ ممیزی ثبت شوند. بدون این، «fallback» فقط در
مستندات است، نه در رفتار. (E1-03 این را پیاده می‌کند.)

## ۴. درگاه پرداخت

| معیار                | زرین‌پال                                                         | زیبال                       | آیدی‌پی |
| -------------------- | ---------------------------------------------------------------- | --------------------------- | ------- |
| سندباکس              | **دارد**: `sandbox.zarinpal.com` با هر UUID به‌جای مرچنت         | **دارد**: مرچنت `zibal`     | محدود   |
| احراز هویت/فعال‌سازی | احراز + نماد؛ ۲۴–۴۸ ساعت                                         | سریع‌تر، معمولاً زیر ۲۴ ساعت | سریع    |
| کارمزد               | حدود ۰.۵٪ + مبلغ ثابت (منابع مختلف ۰.۵–۱٪ + ۲۵۰–۵۰۰ تومان)       | ۱٪ (+ مالیات)               | ۱٪      |
| تسویه                | روزانه‌ی خودکار / دستی                                           | روزانه، سریع                | روزانه  |
| مستندات و SDK        | REST روشن، SDKهای متنوع                                          | REST ساده                   | REST    |
| ریسک عملیاتی         | پرداخت واقعی فقط از **IP ثبت‌شده**؛ سرور باید IP ثابت داشته باشد | وابسته به پنل               | —       |

**قاعده‌ی محصولی (A24):** مسیر اصلی پرداخت **کارت‌به‌کارت با مبلغ یکتا** است و رایگان؛ درگاه فقط
برای اشتراک/پلن. دلیلش هزینه است، نه سلیقه:

- کارت‌به‌کارت: کارمزد صفر، ریسک انسانی تأیید، بدون نیاز به مجوز درگاه.
- درگاه: ۰.۵–۱٪ روی هر تراکنش؛ روی GMV ماهانه این عدد از هر هزینه‌ی دیگری در محصول بزرگ‌تر می‌شود.

پس پیشنهاد: **زرین‌پال فقط برای پلن/شارژ**، با `PAYMENT_GATEWAY=zarinpal` و دو متغیر
`ZARINPAL_MERCHANT_ID` و `ZARINPAL_SANDBOX=true|false`؛ مسیر کارت‌به‌کارت بدون تغییر می‌ماند.
Ingestion پیامک بانکی (E7-05) به منبع پیامک بانکی نیاز دارد و **بدون تصمیم جداگانه‌ی مالک شروع
نمی‌شود**؛ تا آن زمان تأیید دستی ادمین (E7-07) پاسخ عمل می‌کند.

## ۵. هزینه — مدل برای تصمیم

فرض‌های مدل: ۱٬۰۰۰ کاربر فعال ماهانه، هر کاربر ۱ ورود (۱ OTP)، هر کاربر ۲ معامله، میانگین هر
معامله ۳۰۰٬۰۰۰ تومان. سه سرویس، سه ردیف هزینه:

| قلم                                       | محاسبه                        | هزینه‌ی ماهانه (تومان)                                |
| ----------------------------------------- | ----------------------------- | ----------------------------------------------------- |
| پیامک OTP                                 | ۱٬۰۰۰ × ۱ پیامک × ۱۰۰/۱۵۰/۲۰۰ | **۱۰۰٬۰۰۰ – ۲۰۰٬۰۰۰**                                 |
| نقشه (Distance Matrix + Direction)        | ~۳٬۰۰۰ درخواست × ۱۰–۱۵ ریال   | **~۳٬۰۰۰ – ۵٬۰۰۰** (داخل اعتبار هدیه‌ی ماهانه‌ی نشان) |
| درگاه (اگر ۵٪ پرداخت‌ها از درگاه باشد)    | ۵٪ × ۶۰۰M GMV × ۰.۵–۱٪        | **۱.۵ – ۳ میلیون**                                    |
| درگاه (اگر همه‌ی معامله‌ها از درگاه باشد) | ۶۰۰M × ۰.۵–۱٪                 | **۳ – ۶ میلیون**                                      |

نتیجه‌ی مدل: **پیامک ارزان است، درگاه گران است.** هزینه‌ی ماهانه‌ی نقشه عملاً صفر است، و همین
تصمیم D4 را بی‌ریسک می‌کند. هر تصمیمی که تعداد پرداخت‌های درگاهی را کم کند (کارت‌به‌کارت، پلن
سالیانه) مستقیماً حاشیه‌ی سود را بالا می‌برد.

> اعداد تعرفه در تاریخ نوشتن این سند از منابع عمومی گرفته شده‌اند و برای قرارداد کافی نیستند:
> هر سه ارائه‌دهنده قیمت را بر اساس حجم و خط تغییر می‌دهند. قبل از امضا، استعلام کتبی لازم است.

## ۶. Push

| گزینه           | مزیت                                                        | ریسک                                                            | نقش پیشنهادی                                         |
| --------------- | ----------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------- |
| وب‌پوش با VAPID | بدون سرویس خارجی، روی PWA کار می‌کند، کلیدها در سرور خودمان | پشتیبانی iOS ضعیف، نیاز به HTTPS                                | کانال اصلی برای وب                                   |
| FCM             | استاندارد اندروید، تحویل مطمئن در حالت بسته                 | دسترسی از داخل ایران متغیر است؛ کلید و پروژه‌ی Google لازم دارد | M1، با تست شبکه قبل از وعده                          |
| پیامک           | همیشه می‌رسد                                                | هزینه‌ی هر پیام                                                 | **کانال تضمینی اعلان‌های بحرانی** (رزرو، لغو، تسویه) |

قاعده: هر اعلان یک «اهمیت» دارد. اعلان‌های بحرانی (رزرو رد شد، مهلت تمام شد، پرداخت تأیید شد)
همیشه یک کانال تضمینی دارند؛ چت و اعلان‌های خوش‌آمدنِ فقط in-app/وب‌پوش هستند. این قاعده در
`NotificationEmitter` قابل بیان است و به ارائه‌دهنده وابسته نیست.

## ۷. نقشه و مسیریابی (D4)

| معیار                  | نشان                                                                              | بلد                  | OSM خودمیزان (Valhalla/OSRM)       |
| ---------------------- | --------------------------------------------------------------------------------- | -------------------- | ---------------------------------- |
| پوشش شهرهای کوچک ایران | خوب                                                                               | خوب برای شهرهای بزرگ | بستگی به داده‌ی OSM محلی           |
| ETA با ترافیک          | **دارد** (Direction/Distance Matrix)                                              | دارد                 | ندارد (ETA بدون ترافیک)            |
| Geocoding/Reverse      | دارد                                                                              | محدود/استعلام        | Nominatim (کیفیت متغیر برای ایران) |
| تعرفه                  | ~۱۰ ریال برای هر درخواست مسیریابی/ماتریس، ۱۵ ریال با ترافیک؛ اعتبار هدیه‌ی ماهانه | استعلام              | هزینه‌ی سرور (پهنای باند/CPU)      |
| ریسک تحریم/قطعی        | متوسط                                                                             | متوسط                | **صفر** (خودمیزان)                 |
| هزینه‌ی مهندسی         | کم                                                                                | کم                   | زیاد (نصب، آپدیت داده، مانیتورینگ) |

پیشنهاد: **نشان** برای نقشه، Geocoding و ETA؛ و `RouteProvider` همیشه یک مسیر دوم داشته باشد
(haversine امروز، Valhalla در M1). این‌طور اگر کلید نشان کار نکند، «زمان رسیدن تقریبی» نمایش داده
می‌شود، نه خطا. همین الان هم پیش‌فرض بدون کلید همین است؛ تصمیم D4 فقط کیفیت ETA را بالا می‌برد.

## ۸. ریسک‌ها و پاسخ‌ها

| ریسک                   | اثر                             | پاسخ                                                       |
| ---------------------- | ------------------------------- | ---------------------------------------------------------- |
| تحریم/قطعی پیامک       | کاربر نمی‌تواند وارد شود        | دو ارائه‌دهنده + الگوی آماده در هر دو + هشدار در پنل ادمین |
| رد شدن احراز درگاه     | پلن فروش نمی‌شود                | کارت‌به‌کارت پیش‌فرض است؛ درگاه فقط مسیر دوم               |
| نبود IP ثابت           | پرداخت واقعی زرین‌پال رد می‌شود | IP ثابت برای سرور API در M1 الزامی شود                     |
| FCM از ایران           | اعلان اندروید نمی‌رسد           | پیامک به‌عنوان کانال بحرانی، وب‌پوش برای وب                |
| وابستگی به داده‌ی نقشه | مسیر/ETA غلط                    | مسیر دوم بدون ترافیک + نمایش «تقریبی»                      |
| هزینه‌ی درگاه          | حاشیه‌ی سود                     | مسیر رایگان کارت‌به‌کارت، درگاه فقط برای پلن               |

## ۱۰. سؤال‌های باز برای مالک

1. تأیید مسیر اصلی/پشتیبان پیامک (SMS.ir + کاوه‌نگار)؟
2. تأیید زرین‌پال فقط برای پلن/شارژ، با کارت‌به‌کارت به‌عنوان مسیر اصلی معامله؟
3. تأیید نشان برای نقشه/ETA + مسیر پشتیبان بدون ترافیک؟
4. تخصیص IP ثابت به سرور API (پیش‌نیاز پرداخت واقعی)؟
